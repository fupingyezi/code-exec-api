# 限制与已知缺陷（文档 §13）

能说清自己方案边界的实现，才叫实现。本清单随实现更新。

| 限制 | 具体表现 | 影响 | 改进方向 |
|---|---|---|---|
| 单机架构 | 队列、Worker、Docker 全在一台机器 | 无法横向扩容；单机故障 = 服务不可用 | Worker 拆成独立部署单元，多 Worker 消费同一队列 |
| **挂载 docker.sock = 等价 root** | api 容器挂载宿主 sock（compose 附录 C） | 该容器被拿下 = 宿主被拿下 | 独立机器跑 Worker；或 docker-socket-proxy 只放开必需 API；或 rootless Docker |
| 容器池状态残留 | 复用容器靠主动清理 | 清理漏一处就跨任务泄漏 | 已做：工作区每任务清空、残留进程收割、MAX_REUSE 50 兜底；仍有僵尸进程堆积风险（PID1 是 sleep，不收割僵尸，靠 MAX_REUSE 定期重建兜底） |
| 池化源码可见性 | 源码经 argv/stdin 注入（实测偏差 #9） | 同一容器内后续任务理论上可从残留痕迹窥探（已清理） | 接受；冷路径无此问题 |
| 输出截断影响比对 | 超 64 KiB 直接截断 | 调用方拿截断的 stdout 比对会误判 | 已返回 `truncated` 标志 |
| 无文件产物回传 | 只回传 stdout/stderr | 生成图片、编译产物类任务无法使用 | 增加「产物白名单目录」+ 打包回传 |
| 语言版本固定 | 镜像内置，无法装依赖 | 需要第三方库的题目跑不了 | 预装依赖的镜像变体 / 依赖白名单 |
| 5 s 墙钟偏紧 | 大量 IO 或复杂计算会 TLE | 部分题目误判 | 调用方可调（500–15000） |
| 队列不可抢占 | 长任务排在前面阻塞后面的 | 长尾延迟 | 按语言分队列 / job 优先级 |
| 限流是固定窗口 | INCR+TTL 近似令牌桶 | 窗口边界流量毛刺 | 换真令牌桶 |
| colima 下无法容器化部署 | VM 只共享 $HOME | 本机只能用 npm run dev | 换 Docker Desktop / Linux 环境 |
