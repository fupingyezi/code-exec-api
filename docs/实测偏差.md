# 实测偏差记录

文档声明「没有跑过一份真实实现」，本清单记录实现过程中发现的、与文档不符或文档未覆盖的实测问题。每项都已在对应代码注释中标明。M5 的 gVisor 对比报告可延续此格式。

## 1. 文档代码本身的问题

| # | 位置 | 文档内容 | 实测结果 | 修正 |
|---|---|---|---|---|
| 1 | §6.3 镜像 Dockerfile | `addgroup -g 65534 sandbox` | gid 65534 已被基础镜像的 nobody/nogroup 占用，构建直接失败 | 删除创建用户的步骤，复用基础镜像自带的 nobody(65534) |
| 2 | §6.2 dockerOptions | `HostConfig` 里写 `User` 字段（「双保险」） | @types/dockerode 的 HostConfig 没有该字段，TS 编译失败；Docker API 的 User 只在 ContainerCreateOptions 顶层生效 | 删除 HostConfig 里的重复行 |
| 3 | §7.3 capture | 部分截断（单个 chunk 超出剩余预算）不置 `truncated` | 与 §4.2 自己的定义「只要触发过就是 true」矛盾 | 补 `slice.length < chunk.length` 分支 |
| 4 | §8.2 verdict | 代码把 `exitCode 1..128` 归 IE | 与 §8.1 表的 RE（未捕获异常）矛盾 | 按表修正：1..128 → RE；136/138/141/143 等不可解释信号 → IE |
| 5 | §7.2 execute | `remove` 只在正常路径末尾 | attach/start 抛错时容器残留 | finally 强制回收 + 5 次重试 + 泄漏日志 |

## 3. 池化实现的硬约束（§10 未指定实现方式）

| # | 问题 | 结论 |
|---|---|---|
| 9 | `putArchive`（docker cp）注入源码 | daemon 对 ReadonlyRootfs 容器整体拒绝 copy（"container rootfs is marked read-only"），tmpfs 挂载点同样被拒 | 源码改走无文件通道：解释型 argv（`node -e` / `python3 -c`），编译型 exec stdin（`g++ -x c++ -`）；代价是源码在 ps 中短暂可见，由「池容器单任务占用 + 残留清理」控制风险 |
| 10 | Docker tmpfs 默认参数 | 默认 mode=755（root 属主）+ 自动追加 noexec | /tmp 与 /workspace 显式 `mode=1777`；/workspace 显式 `exec`（否则 cpp 产物无法执行，且非 root 用户写不进） |
| 11 | 池容器异步补位与 drain 竞态 | 脏容器销毁后异步预热补位，drain 之后补位容器才到达 → 泄漏 | pending 登记 + disposed 标记，drain 先等补位结束 |
| 12 | 容器回收偶发失败 | 测试文件并行时 VM 负载叠加，remove 偶发失败 | vitest 顺序执行（文档 §11.2 本来就要求连续跑）+ 5 次重试 + 泄漏由隔离用例 10 兜底检测 |
